# Единый реестр вопросов и контрольных действий VARSHAVKA

Дата среза: 4 августа 2026 года.

## Назначение и статус реестра

Этот файл является единым полным реестром решений, незакрытых исходных
данных, рисков, испытаний и корректирующих действий проекта VARSHAVKA.

До создания этого документа в репозитории существовали:

- GitHub Issues для отдельных изменений финансовой модели и сайта;
- `OPEN_QUESTIONS.md` с восемью вопросами ранней версии модели;
- `INPUT_REGISTER.md` с параметрами базовой версии;
- ADR и протоколы проверок.

Ни один из этих источников отдельно не охватывал все вопросы разработки
МЕНЮ КУХНИ, производственной программы, оборудования и БАНКЕТОВ. В исходном
состоянии до формирования этого реестра открытых GitHub Issues не было;
затем созданы тематические Issues #36–#53. Ранний список открытых вопросов
частично устарел: например, питание сотрудников уже разработано, а наличная
модель БАНКЕТОВ в реестре inputs ещё не отражена.

## Правила контроля

1. Каждой записи присваивается постоянный код `V-I-xxx`.
2. Этот реестр содержит все записи, включая закрытые, заменённые и
   контролируемые после запуска.
3. Исполнимые пакеты работ отражаются отдельными GitHub Issues. Детальные
   записи могут ссылаться на одну тематическую карточку.
4. Статусы:
   - `OPEN` — требуется решение или работа;
   - `BLOCKED` — выполнение невозможно без внешних данных;
   - `PLANNED` — способ выполнения и контрольное событие определены;
   - `MONITOR` — решение принято, требуется фактическая проверка;
   - `CLOSED` — критерий выполнен и имеется подтверждение;
   - `SUPERSEDED` — правило заменено последующим решением.
5. Issue закрывается только при наличии ссылки на проверяемый результат:
   протокол, технологическую карту, расчёт, паспорт оборудования, PR или
   утверждённое решение.
6. Изменение рецептуры, финансовой методики или производственного правила
   после утверждения оформляется отдельным решением и при необходимости ADR.
7. Реестр проверяется не реже одного раза в неделю до запуска и ежемесячно
   после запуска.

## Структурная синхронизация S04 v3.0.0

В модели устранено представление незакрытых исходных данных как
подтверждённых фактов:

- `MAX_SEATS = 26` связано с блокирующей записью `V-I-040`, тогда как
  расчётная база сохраняется равной 20 местам;
- `VAT_RATE` явно обозначен блокирующим input по `V-I-054`;
- укрупнённые food cost À la carte, Бизнес-ланча, Доставки, Навыноса,
  гостиничного ужина и БАНКЕТОВ обозначены предварительными прокси до
  выполнения `V-I-053`;
- календарь связан с `START_DATE` и `END_DATE`; фактические банкетные даты
  автоматически сверяются с `BANQ_START`, `BANQ_PER_MONTH`,
  `BANQ_TOTAL`, `BANQ_FSS_SHARE` и `BANQ_WD_SHARE`;
- годовая программа питания сотрудников рассчитывается суммированием
  утверждённых дневных программ, а не умножением 84 комплексов на 52 недели.

Эти изменения не закрывают `V-I-040`, `V-I-053`, `V-I-054` и `V-I-055`:
они устраняют структурное противоречие и обеспечивают контроль открытых
данных, но не заменяют внешние документы и решения владельца.

### Срез готовности Issue #82

Трассировка RC2 разделяет предметные данные и их публикацию:

- `candidate_data_sha=0d22ac8d0bb1ab198dcd18da21f3a8b741d186c1` — точный
  commit входных domain/workbook/QA данных, не изменяемых RegisterSyncAgent;
- `verified_candidate_sha=88859b25963f8d2f99883901201a81ce0fbf0257` — точный
  RC2 candidate, независимо проверенный с run `30832433440`;
- `iv_publication_commit_sha=407105648fa4d58f09027fe6a7967b53823c7e78` —
  commit публикации неизменяемых RC2 report/HOF-0021;
- `final_register_sync_publication_commit_sha` — commit, содержащий точные
  blobs настоящего реестра, `DEFECT_REGISTER.csv`,
  `READINESS_STATUS_REPORT.md` и HOF-0022. Он фиксируется внешней attestation,
  поскольку собственный SHA невозможно встроить в commit без изменения SHA;
- [RC1 Independent Verification](https://github.com/slavagrachov/varshavka-cafe-usali-model/blob/4fec6712b16a8b20d4fe8036d802537da63aff20/docs/07-operations/issue-82/FINAL_INDEPENDENT_VERIFICATION_REPORT_RC1.md):
  `candidate_sha=49cd9f4bd896ea11dc8afbce3a93539f761b52a6`, workflow run
  `30830497424`, verdict `FAIL / NOT_MERGE_READY` из-за IV-016 и IV-017;
- [RC2 Independent Verification](https://github.com/slavagrachov/varshavka-cafe-usali-model/blob/407105648fa4d58f09027fe6a7967b53823c7e78/docs/07-operations/issue-82/FINAL_INDEPENDENT_VERIFICATION_REPORT_RC2.md):
  report blob `7eb1a4182514cdb89b92b3849d60ef9317e9a507`, verdict
  `CONDITIONAL / NOT_MERGE_READY`;
- HOF-0021 blob: `e522f3428ce1c0936e93271f353a0830ab749802`.
