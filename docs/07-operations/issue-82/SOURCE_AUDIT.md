# Source Audit — Issue #82 / Gate A

Статус: **PASS_WITH_CONDITIONS**
Дата среза: 2026-08-03
Агент: `/root/source_auditor_replacement`
Scope: `VKM-001…VKM-025`, `VKM-029…VKM-031` (28 позиций); `VKM-026…VKM-028` — только архитектурный эталон.

## Вывод

Локальных источников достаточно, чтобы начать проектирование 28 комплектов со статусом `DRAFT_WITH_ASSUMPTIONS`, сохранить постоянные коды `VKM/VKC/VKT`, состав меню, проектные выходы/каналы и воспроизводимую архитектуру. Источников недостаточно для утверждения рецептур, потерь, фактических выходов, цен, сроков/температур, аллергенов конкретных SKU, пищевой ценности, производительности конкретных моделей оборудования и продажных цен.

Gate A пройден только при соблюдении ограничений:

1. `SOURCE_REGISTER.csv`, `EVIDENCE_MATRIX.csv` и `GAP_REGISTER.csv` являются обязательным upstream для всех агентов.
2. Неподтверждённое числовое значение хранится как `null`, а не `0`.
3. Проектные нормы меню переносятся только как `DRAFT`; результаты расчёта — `CALCULATED`; внешние факты без первичного документа — `BLOCKED` или `BLOCKED_PENDING_VALIDATION`.
4. PR #81 не является base или утверждённым источником фактов: разрешены только проверенные коды, архитектура, builder, проверки и три завтрака как пример.
5. Ни одно блюдо не может получить `APPROVED` без решения владельца и шеф-повара; FoodSafetyAgent сохраняет veto по safety-critical полям.

## Иерархия источников

1. Утверждённая рецептура или письменное решение шеф-повара/владельца.
2. Действующий нормативный или профессиональный сборник.
3. Официальный документ производителя/поставщика.
4. Проверяемый профессиональный источник.
5. Явно маркированное проектное допущение.

Репозиторные модели и PR #81 подтверждают архитектуру и состояние проекта, но не заменяют уровни 1–3 для рецептур, закупок и безопасности.

## Разрешённое использование локальных источников

- `KITCHEN_MENU_VARSHAVKA_v3.0.0.xlsx` и `KITCHEN_MENU_3.0.0.md`: состав, наименования, разделы, единицы продажи, проектные выходы, производственная модель и каналы; выходы остаются `DRAFT` до #37/#39.
- Capacity/equipment S04: предварительная потребность, группы функций, нагрузочные гипотезы и CAPEX-разрывы; не паспортная производительность и не подтверждение наличия/подключения.
- S04 и Issue Register: статусы, зависимости и блокеры; процентные COGS не заменяют рецептурную себестоимость (`V-I-053`).
- PR #81: стабильные коды, 10-листовая архитектура, builder и контрольные паттерны; 28 пустых `BLOCKED`-скелетов не являются результатом Issue #82. Завтраки — только пример связей.

## Ключевые конфликты и замещения

- 31 активная позиция заменила исторический состав из 33; две исключённые позиции — `SUPERSEDED`.
- Scope #82 исключает завтраки `VKM-026…028`, хотя они остаются активными в общем меню.
- ADR-0004 заменяет ADR-0002 для банкетного дня; прямого изменения рецептур 28 позиций это не создаёт.
- ADR-0006 и процентные COGS S04 пригодны для сценарной модели, но не для калькуляционных карт Issue #82.
- PR #81 имеет статус reference-only и не может молча переносить значения.

## Gate A acceptance

`PASS_WITH_CONDITIONS`: все существенные семейства параметров получили EvidenceID, источник/метод, дату/версию, статус, владельца подтверждения и связанный gap. Wave 1B может начинаться с проектными данными, сохраняя блокировки из `GAP_REGISTER.csv`.
